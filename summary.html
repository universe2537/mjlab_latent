2026-05-28 Continuous Tennis Redesign

  • Mjlab-Tennis-Continuous-Unitree-G1 now uses a dedicated continuous ball state machine in tennis/mdp/ball_state.py instead of reusing the Cross/Hit tracker as a multi-ball rally state.
  • Incoming feeds are sampled from bird's-eye ground endpoints by OpponentFeederCfg: start points are in the opponent half (x < 0) and target points are in the robot half. Both endpoints use the ball-center ground height GROUND_Z; the feeder solves the upward velocity from a flight time whose lower bound is computed from the required net-clearance height, so generated feeds should clear the net by construction.
  • Invalid opponent feeds, such as an incoming net touch before the robot has a chance to hit, are counted in metrics but are not robot failures. Robot faults are reserved for missed aerial interceptions, return-side out-of-play, net contact after robot return, low net crossing, failed opponent-court landing, or extra racket contacts.
  • Continuous adds a ball-net contact sensor ball_net_contact, replaces old continuous_rally_failure with continuous_ball_fault, and terminates rally success through continuous_rally_complete.
  • After each successful return, the next feed is delayed by a recovery interval. The wait curriculum starts at 3-5s, moves through 1-2s, and ends at 0.3-0.5s. During recovery, the ready-pose reward is active and old-ball faults are ignored.
  • Continuous still warm-starts from the old Cross checkpoint, but its runner config now sets reset_resume_progress=True. That loads model weights while resetting optimizer, iteration, RND, and saved environment progress, preventing old checkpoint step counters from skipping the easy curriculum stages.
  • Verified checks: uv run ty check src/mjlab/rl/runner.py src/mjlab/tasks/tennis tests/test_tennis_task.py tests/test_tennis_hit_state.py, uv run pytest tests/test_tennis_task.py tests/test_tennis_hit_state.py -q, and a CPU construction smoke test for Mjlab-Tennis-Continuous-Unitree-G1.

Tennis Task Notes

Task Purpose Important Detail
Mjlab-Tennis-Cross-LAB-Unitree-G1 Cross task with LAB around the frozen distillation decoder prior. Best route so far is from the non-LAB Cross checkpoint, not from Hit-LAB.
Mjlab-Tennis-Cross-Wrist-LAB-Unitree-G1 Adds 3 right-wrist residual dimensions on top of the old Cross latent action. Despite the legacy task name, the current recommended config preserves non-LAB Cross action semantics: LAB is disabled, wrist residual scale is small, migration std is low, and wrist residual penalties are strong.
Mjlab-Tennis-Continuous-Unitree-G1 Attempts multi-ball rallies by delaying the next feed after each successful Cross-style return. Continuous now has an explicit recovery phase: successful landing starts a countdown, the actor/critic see only a 3-way phase one-hot, ready-position recovery is rewarded, and respawn happens only after the countdown.
Mjlab-Tennis-Hit/Cross-SONIC-Unitree-G1 Direct 64-dim SONIC token control. Future run names mark this as wo_encoder; direct token PPO can leave SONIC's valid token manifold and produce strange motion.
Mjlab-Tennis-Hit/Cross-SONIC-Encoder-Unitree-G1 Uses SONIC encoder as a token prior and trains residual token actions. Encoder input is built from current G1 proprio/history as a pragmatic prior; it is not a perfect motion-reference encoder replacement.

SONIC Encoder Integration

  • Local checkpoint link: ckpt/GEAR-SONIC points to /data0/universe/ckpt/GEAR-SONIC.
  • SONIC decoder ONNX input is 994 = 64 token + 10 * (6 + 3 * 29). The existing action term feeds token, angular velocity history, joint position/velocity history, last action history, and gravity history.
  • SONIC encoder ONNX input is 1762 and output is 64. For the G1 encoder mode, the useful slices are mode one-hot, 10-frame joint position history, 10-frame joint velocity history, and 10-frame anchor orientation history.
  • The exported encoder had fixed-batch Reshape constants such as [1, 1, 10, 6]. The action term now patches Reshape shape constants whose first dimension is fixed to 1, replacing it with -1 so vectorized env batches work.
  • The encoder-prior token currently uses: token = encoder(current_proprio_history) + 0.2 * tanh(policy_action), followed by the configured token clip.

Tennis Deployable Observation Notes

  • Tennis actor ball history now uses torso_to_ball_b instead of racket_to_ball_b. The dimension is unchanged (10 * 3), so old latent policy checkpoints still have a compatible first layer, but the semantics of that slice changed.
  • Keep precise racket-site quantities such as racket_to_ball_b and racket_velocity_b in critic observations, rewards, and contact logic. They are useful asymmetric-training signals but should not be required actor inputs for deployment.
  • Continuous continuous_ball_phase now returns only [incoming, return_flight, recovery]. The removed recovery_fraction_remaining and normalized return-count are still internal metrics/state but no longer policy observations.
  • predicted_hit_point and approach_point now prefer the descending intersection with the hit-height plane. The old logic picked the earliest positive root, which could target the upward crossing near the opponent feed; in a Continuous reset sample that looked like x=3-8m and t=0.07-0.18s. After the fix, the same sample is around x=-0.08..1.65m and t=0.81..1.45s.
