Tennis RL

Human-Like Tennis Environment

从比赛规则出发，而不是从当前 reward 拼接出发

北极星 系统分层 规则状态机 课程学习 落地路径

Design Brief

把网球环境设计成一场比赛，而不是一次击球。

最终目标不是“拍到球”，也不是“让球朝某个方向飞”，而是让 humanoid 在一套逐步加严的规则里，学会像人类一样完成发球、接发、相持、得分与失分决策。 因此环境的第一原则应是：规则先于奖励，比赛状态先于终止条件，课程先于完整复杂度。

核心抽象 规则状态机 + 生成器 + 课程
训练单位 以 point 为最小闭环，以 match 为长期上下文
方法论 先简化规则，再逐层逼近真实网球

世界坐标

建议固定球网为世界坐标的唯一语义中轴，所有 side、serve、landing、out 判定都以 court-relative frame 定义。

Agent side / own half
Target / opponent half
Ball state and trajectory
Net plane as rule boundary

设计原则

Rule First 先定义 legal / illegal event，再写 reward。
Point First 先学会赢下一分，再考虑整局、整盘与整场。
Curriculum First 先学 one-shot hit，再学过网、落点、相持、发球。

一句话架构

Physics state → Event detector → Rule state → Reward / Termination / Metrics

Singles first Scripted opponent first Point scoring first

最小闭环

Serve or incoming ball 球生成器把一分送入可学习的起点。
Valid return 机器人完成合法接触、过网与落点。
Point result 规则层决定这一分谁赢，而不是 reward 凭经验猜。

推荐起点

第一版完整环境建议：单打、无 let、point-only scoring、scripted ball launcher / scripted opponent、latent low-level control。

环境分层

先抽象层，再落回具体的 manager、reward、termination 或 decoder 接口。

Layered Architecture
World Layer 场地与物理世界

Court Geometry

边线、底线、发球线、服务盒、网平面、可玩区域、target zone 都作为独立语义区域定义。

Dynamic Entities

ball、agent、opponent、racket 及其 contact / bounce / crossing 可观测事件。

Rule Layer 比赛规则状态机

Legal Event Semantics

合法接触、过网、首次落地、界内/界外、二跳、双误、漏球都在此层定义。

Point Lifecycle

一分从 serve_setup / incoming_ball 开始，到 point_over 结束，不和 RL episode 强绑定。

Interaction Layer 生成器与对手

Ball Generator

按 phase 生成球：静态球、背离网球、incoming return、serve trajectory、scripted rally ball。

Opponent Model

从最初的 ball launcher，到 scripted opponent，再到 learned opponent / self-play。

Learning Layer reward、termination、metrics

Reward Reads Rule State

reward 不定义 legality，只读取规则层输出的 event 与 result。

Termination Ends The Rollout

termination 表示 rollout 边界，不应该替代 point result 或 scoring rule。

规则状态机

当前 one-shot hit state 只是一种 proof-of-concept。最终结构应覆盖 serve、return、rally 与 point result。

Finite-State Rule Engine
Physics 球、拍、地面、网、身体的连续状态。
Event Detector contact edge、bounce edge、net touch、crossing、landing。
Rule State phase、hitter、fault、bounce、winner、score context。
Outputs reward、termination、metrics、curriculum adaptation。
Phase 01 reset 统一重置一分所需的球、人、side、serve context 与 opponent context。
Phase 02 serve_setup 发球方、发球盒、fault count、站位合法性确定。
Phase 03 serve_hit / serve_flight 发球出手、过网、发球盒判定、fault / let / in。
Phase 04 return_ready 接发方等待回球窗口，合法击球机会开始。
Phase 05 rally 双方轮流击球，跟踪 net、landing、bounce、out、miss。
Phase 06 point_over point winner 与 result 写入 score state，并决定是否继续 game / set / match。
核心状态字段

phase, last_hit_side, expected_receiver_side, fault_count, bounce_count_per_side, ball_crossed_net, first_landing_pos, first_landing_in, second_bounce, point_winner, point_result

设计原则

不要把合法击球、出界、得分等规则散落在 reward term 里。所有 rule event 必须先进入同一个状态机，再由训练信号读取。

人类网球规则到 RL 的映射

不是所有真实规则都要第一天完整模拟，但必须知道哪些是北极星，哪些只是阶段性简化。

Rules To Learning Signals
必须直接模拟 发球是否合法、是否过网、首次落地是否界内、二跳、出界、漏球、网碰撞、point winner。
可阶段性简化 let、deuce / advantage、set / match scoring、复杂发球站位、spin 精确建模。
适合做 Reward intercept 准备、有效接触、过网 margin、landing target、相持成功、point win。
不应只做 Reward out、net、double fault、second bounce、miss。它们先是规则事件，再可能伴随惩罚。
适合做 Metrics serve-in rate、valid return rate、landing-in rate、rally length、point win rate、double fault rate。
适合做 Curriculum Knobs 球速、球高、落点难度、网约束严格度、目标区大小、对手质量、point duration 上限。

球与对手生成规则

“球怎么来”决定了 agent 在学什么。生成器应由 phase 与 curriculum 控制，而不是只有 reset 随机化。

Generators

Ball Generator

按阶段生成 stationary easy-hit ball、away-from-net ball、incoming return、serve flight、scripted opponent return。参数包括 spawn side、spawn region、height、velocity、spin placeholder 与 target intent。

spawn_side speed_range height_range target_intent

Opponent Model

从 ball launcher 到 scripted opponent，再到 learned opponent / self-play。建议先让“对手能力”作为课程参数，不把 humanoid 对手学习和 agent 基础击球学习绑死。

launcher scripted return reactive opponent self-play

课程学习蓝图

完整网球规则应当渐进引入，否则 reward 过稀疏、credit assignment 过长、行为容易坍缩。

Curriculum Roadmap
S1

One-Shot Directional Hit

只要求一次有效击球，把球打离球拍并朝对方半场飞行。先消除 juggling、贴球与无效挥拍。

S2

Net Clearance + Landing

引入过网和首次落地区域，目标从“打出去”升级为“合法打过去”。

S3

Incoming Return

球从对方半场飞来，agent 需要在合法时间窗口内回击，而不是等待友好的初始球。

S4

Scripted Rally

加入可控质量的 scripted opponent，开始学习多拍相持与 point result。

S5

Serve + Return

发球盒、fault、double fault、return ready 全部进入规则状态机。

S6

Scoring Pressure + Opponent Variation

从 point-only scoring 提升到 game scoring，并引入对手差异、落点策略和局面压力。

Observation / Action / Score

高层 tennis policy 和低层 humanoid controller 不应该共享同一套语义边界。

Interfaces

High-Level Observation

proprioception、ball kinematics、court-relative geometry、rule bits、target context、opponent context、score context。

Low-Level Control

若继续使用 latent decoder，低层只需要稳定的人形运动控制状态；高层 game state 不应直接污染 decoder state。

Point Scoring

训练先做 point-only，评估时再读 game scoring / deuce / advantage；score 是上下文，不是最初唯一 reward。

Episode Semantics

一分结束不一定意味着整个 RL episode 结束。后期应该允许多 point 同 episode，以学习策略性与比分压力。

如何映射回当前项目

先定抽象，再决定放进哪个 manager。不要因为当前 one-shot tennis 的 wiring 已经存在，就让它限制结构设计。

Implementation Mapping
TennisRuleState 作为 stateful shared object，供 reward、termination、metrics 读取。它应取代当前仅服务于 one-shot hit 的局部状态对象。
Ball / Opponent Generators 优先挂在 reset / step events 或 command-like generator 上，让生成过程按 phase 与 curriculum 调整。
Scoring State 作为规则层的独立子状态，point result 更新它，而不是让 reward 或 termination 顺手维护比分。
Reward / Termination Terms 保持为 thin readers：只读取已决策完成的 rule event，而不是自行判断 legality。

推荐第一版完整环境

  • Singles only
  • Scripted ball launcher / scripted opponent
  • Point-only scoring for training
  • No let at the beginning

验证重点

  • serve-in rate
  • valid return rate
  • landing-in rate
  • rally length
  • point win rate

架构警戒线

  • 不要让 reward 定义规则
  • 不要把 point result 和 episode 绑定死
  • 不要让当前 one-shot 实现反过来约束最终设计
